# 按任务需要选择执行流程

2026-09-07，用户确认以下设计方向。当前所有实现任务都必须创建 worktree、重叠范围默认阻塞、收口依赖 Agent 串联命令的规则增加了轻量工作的成本；将流程约束集中于需要隔离和协调的任务，同时保留交付验证与文件保护。

## 已确认的规则

- Agent 判断任务轻重并简述理由，无需逐次请求批准。范围明确、低风险、可直接验证的任务默认 inline 完成，不登记 Requirement；需要拆分协作、依赖协调或隔离实验的任务使用完整流程。文件数量不作为硬门槛。
- Agent 负责选择提交内容并完成提交。此后一个命令完成检查、合并、验证、清理 worktree 和标记完成；失败保留现场，修复后重跑同一命令。验证必须先于现场清理。
- 同模块或同文件的任务可以在独立 worktree 并行修改。Agent 记录修改分工、合并顺序和整体验证方式后自行放行，无需用户逐次授权；向目标分支的合并串行进行，实际冲突由 Agent 处理。
- 根据任务开始前的文件记录和显式声明区分任务产物与本地文件，不靠文件名猜测。不影响合并的本地文件允许保留；清理 worktree 前，未提交产物与仅存于其中的配置必须先得到保存，不能因为与任务无关就删除。

- 轻量任务执行中出现协作或隔离需要时，Agent 自动升级为受管任务并把本任务已有改动带入新 worktree，保留原有工作。
- 清理时自动将已分类的本地配置和非交付文件保存到 worktree 外、按执行尝试区分的目录，并返回保存路径；未分类的新文件暂停清理，由 Agent 明确归属后重试，避免遗漏应提交的源码。

这些目标行为已进入实现与验收。实现和验收范围见 [规格](../specs/adaptive-task-workflow.md)。

## 决策时的实现暴露的问题

- `src/agent-instructions.ts` 对全部实现任务要求登记并创建 worktree；只增加 inline 命令不能消除入口的强制要求。
- `src/scheduler.ts` 根据范围重叠阻塞调度；`start --force` 的例外尚未形成调度器可复用的协调计划。
- `src/cli.ts` 当前先 cleanup 再在 done 中验证；验证失败时执行 worktree 已被删除。
- `src/git.ts` 的合并检查与删除检查共用同一干净状态判断。普通 ignored 文件没有进入该检查，但删除使用 `git worktree remove --force`，文件保护必须覆盖这类内容。
