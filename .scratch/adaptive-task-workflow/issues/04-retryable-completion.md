# 04: 用一个可重试的命令完成受管任务

**What to build:** Agent 提交变更后调用统一入口，完成检查、合并、验证、文件保全、现场清理和任务完成。失败保留现场，修复后重跑同一命令即可继续。

**Blocked by:** 02: 放行无关本地文件，并在清理前自动保全。

**Status:** done

**Spec:** [按任务需要选择执行流程](../../../docs/specs/adaptive-task-workflow.md)

- [x] 统一入口覆盖全部收口步骤，正常路径无需 Agent 串联底层命令；帮助、JSON 结果、Agent 指令和中英文说明一致。
- [x] 验证在已合并的目标工作区运行，并先于 worktree 删除；无验证命令时明确报告未运行项目验证。
- [x] 验证失败保留可继续修改和提交的任务 worktree；修复后重跑整合最新提交并重新验证，不隐式回滚目标分支。
- [x] 合并前持久化操作意图。Git 已完成但状态写入中断时，重试使用真实提交证据恢复，不能仅根据祖先关系认定已交付。
- [x] 冲突保留在实际发生的现场；Agent 解决并继续 Git 合并后，重跑统一入口可核对和补录结果，随后继续验证与清理。
- [x] 验证结果绑定实际被验证的提交；源或目标发生变化后不复用过期结果。
- [x] 文件保全失败或出现未分类内容时返回具体下一步操作，保留现场且不标记完成；再次调用可继续保全与清理。
- [x] 沿用已有锁串行保护目标工作区；CLI 并发调用不能交叉合并和验证或记录错误的完成状态。
- [x] 已完成时重复调用返回已有结果；对部分完成和中断状态基于可验证证据继续，不重复合并或删除。
- [x] 现有底层命令如保留，需有明确的诊断或修复用途，并遵守同一完成约束；不保留使验证晚于清理的旧完成路径。
- [x] CLI 集成测试覆盖成功、重复调用、验证失败后修复、冲突解决后继续、Git 成功但状态写入失败、保全失败、清理中断与并发调用。
- [x] 与并行协调任务都完成后，验证统一入口遵循协调计划；所有任务完成后运行完整构建和现有测试。
