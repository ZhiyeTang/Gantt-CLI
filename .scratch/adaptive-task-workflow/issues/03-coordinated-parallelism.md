# 03: 已有协调计划的重叠任务可以并行

**What to build:** Agent 记录参与任务、修改分工、合并顺序和整体验证方式后，可自行调度和启动修改同一模块或同一文件的任务；实际修改保持独立 worktree，目标分支合并遵循顺序并串行执行。

**Blocked by:** None (can start immediately).

**Status:** done

**Spec:** [按任务需要选择执行流程](../../../docs/specs/adaptive-task-workflow.md)

- [x] 协调计划作为现有记录体系中的持久化信息可被 Agent 写入和读取，包含参与任务、分工、合并顺序和整体验证方式。
- [x] schedule、启动及活动任务范围更新共同识别计划；有效计划覆盖的重叠能够放行，其他重叠保留明确的阻塞说明。
- [x] 集成指令不再要求用户逐次授权已协调的并行安排；计划记录足以审查放行依据，单纯宽泛豁免不能代替计划。
- [x] 原有依赖继续决定任务何时可开始；合并顺序只约束集成，不把可并行开发的任务转换为启动依赖。
- [x] 未列入计划的第三项任务不能继承豁免；任务范围或参与者改变后重新检查相关重叠是否仍被计划覆盖。
- [x] 目标分支合并遵循计划顺序并沿用现有串行保护，范围声明仍约束实际提交；遇到 Git 冲突保留现场交给 Agent。
- [x] 用真实 Git CLI 场景证明同文件任务可并行启动且有序整合，并覆盖未协调任务、真实依赖、越界提交及计划范围改变。
- [x] 与自动收口任务都完成后，验证统一入口也遵循相同的计划与合并顺序。
