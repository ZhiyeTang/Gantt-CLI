# 01: 轻量任务直接完成，复杂后自动升级

**What to build:** Agent 在登记任务前判断是否需要隔离或协作并简述理由。轻量任务默认 inline，不登记 Requirement、不创建 worktree；执行中任务变复杂时自动升级并保留本任务已有改动。

**Blocked by:** None (can start immediately).

**Status:** done

**Spec:** [按任务需要选择执行流程](../../../docs/specs/adaptive-task-workflow.md)

- [x] Agent 集成指令、安装到仓库的入口说明及中英文用户说明一致地先分流，再按需登记；移除所有“全部实现任务必须创建 worktree”的规则。
- [x] 分类依据是范围、风险、可验证性及协作或隔离需要，文件数量不作为硬门槛；Agent 无需逐次请求用户批准。
- [x] 轻量任务沿用正常开发和验证方式，不创建单独 inline 状态体系。
- [x] 任务升级时 Agent 创建受管任务及独立 worktree，转移并核对本任务已有改动，原有无关修改保持原状。
- [x] 无法区分本任务与既有修改时保留原状并报告具体歧义，不能全量搬走或清空原工作区。
- [x] 沿用现有测试验证输出的指令契约，并用临时仓库演练有无关修改时的升级过程；明确区分指令检查与真实 Agent 判断能力。
- [x] 完成后构建和相关 CLI 测试通过。
